# FP32 vs INT8 at optimization_level 0 — the quantization itself is not the fault

Run 2026-09-06 on Colab (Tesla T4, DFC 3.33.1, Python 3.10) against **`f8f85a5d`**, the
deployed production detector. Emulator only — no device, no full compile.

## Result

```
FP32 (pre-quantization)    above_th=17    max=0.934   per_class={'person': 17, 'sack': 0}
INT8 (quantized, opt-0)    above_th=15    max=0.918   per_class={'person': 15, 'sack': 0}

retained 88% of detections, peak score ratio 0.98
```

Threshold 0.20, matching the `nms_scores_th` baked into the HAR. Eight real frames from
`ψ/active/2026-08-31_capcut-frame-extract/raw2`. Those frames contain people and no sacks,
so this exercises the person class only — sufficient for a like-for-like comparison, but it
is **not** evidence about sack recall.

## What it closes

Quantization at optimization level 0 costs about 2% of peak score. That is ordinary INT8
degradation, not a collapse. Combined with the earlier eliminations, the field is now:

| Suspect | Status |
|---|---|
| Missing cls sigmoid in our ALLS | Eliminated — DFC applies it itself, recorded in the HAR |
| Wrong `regression_length` / decoder-to-stride mapping | Eliminated from HailoRT source: gives bad boxes with healthy scores |
| Normalization mismatch | Eliminated — matches ultralytics' expectation |
| Quantization itself, at opt-0 | **Eliminated here** |
| `optimization_level: 2` | **The remaining candidate** |

Everything measurable has passed. The only variable the broken build had that this run did
not is optimization level 2 — quantization-aware fine-tuning, which matches the 2026-07-21
dead-HEF incident in shape and mechanism.

This also vindicates decisions taken before the evidence existed: the schema defaults
`optimization_level` to 0, and the validator refuses level 2 with fewer than 1024
calibration images.

## Side observation

The INT8 pass logged, at opt-0:

```
layout failed: Size of values 1 does not match size of permutation 4
@ ... probe_1/normalization1_1/act_op_1/SelectV2 ... LayoutOptimizer
```

That is verbatim the TF Grappler layout bug recorded in the 2026-06-23 lesson on the
normalization `SelectV2` node — the reason `optimization_level=0` was adopted in the first
place. Here it is a warning that does not stop inference; at level 2, with full Layer Noise
Analysis, it is what killed `optimize()`.

## Not yet done

The decisive next step is the same comparison **at optimization_level 2** on the same
frames and the same model. If INT8 collapses there and holds at 0, the cause is proven
rather than inferred. It needs a GPU session and roughly 1024 calibration images.
