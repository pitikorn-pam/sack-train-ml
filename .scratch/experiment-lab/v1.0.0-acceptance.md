### A note on the word "v1.0.0"

The repo already emits artifact versions named `1.0.0-<run_id[:8]>` — `scripts/train_for_run.py:132` is the only place a semver is assigned, and it is hardcoded, so every run in history is a `1.0.0-` prerelease.
The goal's "v1.0.0" is the **product** version of sack-train-ml, not that artifact semver.
This document uses **v1.0.0** exclusively for the product. Any acceptance line about artifact naming says "artifact semver".

### Is the repo in better shape than the brief implies?

Partly, and it deserves saying before the defect list.

- The three baseline suites all pass, unmodified, first try (Part 2).
- The parameter contract is real, not aspirational: one JSON file at `contracts/param-schema.json` is genuinely imported (not copied) by the browser (`apps/web/src/lib/schema.ts:10`), by the edge function (`supabase/functions/_shared/contract.ts:19`) and by the Vite alias (`apps/web/vite.config.ts:8-12`).
- The Lab UI is unusually honest about its own limits — it renders LOCKED panels with a backend-supplied reason rather than inventing numbers (`apps/web/src/sections/Lab.tsx:577,586,587,588,593`), and `apps/api/lab_server.py:746` labels its run history `"persistent": False` out loud.
- The provenance story (requested → resolved → effective) is designed in three layers and each layer has a real writer: `supabase/migrations/20260905100009_requested_config.sql:18`, `supabase/functions/start-training/index.ts:88-94`, `scripts/train_for_run.py:235-278`.

What follows is therefore not "this repo is bad".
It is: several load-bearing wires are cut, and nothing currently in the test suite would notice.
